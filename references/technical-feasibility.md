# Technical Feasibility

For each required component record capability, build/buy/partner option, maturity, data need,
integrations, scale target, security/privacy exposure, failure consequence, and cheapest validation spike.

Readiness states: `READY`, `ADAPT`, `R&D`, `UNKNOWN`.

Assess algorithmic complexity, data, integrations, concurrency/scale, security/compliance, AI/ML,
UX/platform breadth, novelty, observability/reliability, and migration/interoperability.

Do not turn a generic complexity score into a fake timeline. Estimate the actual work breakdown.
A technical blocker exists when no credible implementation or validation path fits the decision horizon/capital.
